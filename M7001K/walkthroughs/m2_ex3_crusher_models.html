Exercise 3: comparison of crusher models

module 2 · King 5.1-5.6 (Tables 5.3-5.7)

The exercise sheet and the worked files live on the PC copy of Malla; the sheet's numbers are transcribed in this guide.

What they ask

Build a test rig, not a plant: one common feed, split into as many parallel lines as there are crusher models for a machine type, one model per line, every other setting identical. Then compare the products.

  • Feed: Kiruna D-ore, ρs 4.0 t/m³, 100 t/h per machine, size distribution RRS with d63.2 = 100 mm and n = 1, ten fractions.
  • Annotate the model name beside each machine; fly-outs on the feed and on every product.
  • Jaw crushers first, all at OSS 50 mm: plot feed and products in one particle-size diagram; then raise the feed rate by 50 % and see what changes.
  • Repeat for gyratory crushers (OSS 50 mm), cone crushers (CSS 25 mm), roll crushers (CSS 25 mm) and high-pressure roller mills (CSS 25 mm).

Why (the engineering)

The exercise sheet says it plainly: you will often have to choose between models you only partly understand. A parallel rig with identical data is the cleanest way to see what each model actually does with a setting, because the only thing that differs between lines is the model.

Two things to look for, both from the lecture slides and the MODSIM manual:

  • Which setting drives the product. The primary-crusher models (JAW1, JAW2, GYRA) produce a standard size distribution scaled by the open-side setting and the material type; the feed size distribution does not enter at all (the product is only capped at the largest feed size). The secondary and tertiary models (CRSH, SHHD) run the crushing cycle: internal classification between k1 = α1·CSS and k2 = α2·CSS, then breakage with the two-term Whiten function, repeated until the material escapes. CRS1 is the one-parameter Symons model for preliminary work.
  • Whether the model knows about throughput. None of these crusher models carries a capacity term: a machine model happily "crushes" 150 t/h with the same product it gave at 100 t/h. That is exactly what the +50 % sensitivity is meant to show you. The capacity check is yours, against King's Tables 5.4 to 5.7, and Assignment 1 asks for it explicitly.

Before MODSIM: numbers by hand

The feed. Rosin-Rammler-Sperling (RRS): cumulative fraction finer P(d) = 1 − exp(−(d/d63.2)^{n}). With d63.2 = 100 mm and n = 1 the curve is simply P(d) = 1 − e−d/100:

Size (mm)Cum % finer
109.5
2522.1
5039.3
10063.2
20086.5

So d80 ≈ 161 mm (solve 1 − e−d/100 = 0.8 → d = 100·ln 5) and d99 ≈ 460 mm: your size classes must reach about 500 mm at the top and go down to a few millimetres so the cone products at CSS 25 mm have somewhere to land.

What the simple jaw and gyratory models will give. The standard curve (slide 21, Excel PrimCrushProd) is written in the reduced size r = d/OSS; the coarse end follows P = (r/1.25)^{0.843} for r ≤ 1.25. Two numbers fall out immediately: nothing coarser than 1.25 × OSS = 62.5 mm leaves the machine, and about (1/1.25)^{0.843} = 83 % of the product is finer than the OSS itself. Write both down; they are your first check after the run.

What the cycle models will do at CSS 25 mm. With CRSH defaults α1 = 0.653 and α2 = 1.6, particles finer than k1 = 16 mm pass the chamber unbroken, particles coarser than k2 = 40 mm are always nipped, and the range between is shared according to the classification exponent. SHHD uses α2 = 2, so its "always broken" limit sits at 50 mm. K = 0.2 is the fraction of fines produced per breakage event.

Why

Splitting the feed. If you run five jaw models, the feed to the splitter is 500 t/h and every branch gets 20 %. The exercise wants 100 t/h in each machine, so size the splitter from the number of lines, not the other way round. At +50 % the splitter stays at equal fractions and the feed rises to 750 t/h.

Step by step in MODSIM

Set up ONE family (the jaw crushers) completely, save it, then copy the flowsheet for the next family and only swap models and settings.

1

New job, dry, no minerals, size classes 1 to 500 mm

ClickFile > New job. System data: dry process, no minerals. Size classes: top size 500 mm, root-two series down to about 1 mm
ExpectAbout 18 to 20 classes; the finest classes only matter for the cone, roll and HPGR runs
WhyA mesh that stops at 25 mm cannot show what a CSS 25 mm machine did to the fines
The GUI keeps sizes in metres: 500 mm is 0.5
2

Feed: 100 t/h per machine, RRS d63.2 100 mm, n 1

ClickFeed stream > solids flow (100 t/h times the number of lines) > density 4.0 > size distribution as cumulative % finer at your class sizes
ExpectThe entered curve passes 39.3 % at 50 mm and 63.2 % at 100 mm
WhyRRS.xls in the auxiliary routines generates the ten points for any d63.2 and n; paste them rather than typing e-powers by hand
Ten fractions is how the sheet describes the feed; MODSIM can still carry more size classes than that
3

Draw the rig: feed, splitter, one crusher per model, one product each

ClickFeed > Splitter. Splitter > JAW1, JAW2, EMJC, CRSH (as many lines as models). Each crusher > its own product stream, annotated with the model name
ExpectFly-outs on the feed and on every product; model codes readable beside every icon
WhyThe annotation IS the deliverable: the plot only makes sense if you can tell which curve is which model
A splitter with unequal fractions makes the comparison meaningless. Check the fractions before the first run
4

Give every jaw model OSS 50 mm and the same work index

ClickJAW1 and JAW2: open-side setting 0.050 m, impact work index 12 kWh/t. EMJC: crusher gap 0.050 m, defaults for r_max and m. CRSH: setting 0.050 m (read as OSS for jaw duty), K 0.2, Wi 12, alpha1 0.653, alpha2 1.6
ExpectEvery form shows 0.05 in the setting field, in metres
WhyThe exercise fixes only the OSS; the work index only feeds the power estimate, so one common value keeps the comparison fair (12 kWh/t is the Kiruna value used in Exercise 4)
50 typed into a field that expects metres is a 50 m gap: the product will be the feed, unchanged
5

Run, then plot feed and all products in one size diagram

ClickRun. Graphs > particle size distributions > select the feed and every product stream. Export the plot
ExpectJAW1, JAW2 and GYRA-type curves end at 62.5 mm with about 83 % finer than 50 mm; CRSH shows a different shape with the fines fraction from K
WhyThis is the "what does each model do with the same setting" picture the sheet asks for
6

Sensitivity: feed +50 %, run again, overlay

ClickFeed stream > solids flow times 1.5. Run. Same plot
ExpectThe standard-distribution models do not move at all; the cycle models should not move either, because none of these models has a capacity term. The power in the unit reports rises with the tonnage
WhyThe lesson is the absence: MODSIM will not tell you a crusher is overloaded. King's capacity tables and Assignment 1 do
If a curve does move, note which model and why before believing it (a convergence issue or a changed setting is more likely than a throughput effect)
7

Save as PAK, then repeat for the other families

ClickPack the job as Ex3_jaw.PAK. Copy the flowsheet; swap models and settings: GYRA and CRSH at OSS 50 mm; CRS1, CRSH, SHHD at CSS 25 mm; the roll-crusher and HPGR models MODSIM lists under the mill icons, at CSS 25 mm
ExpectFive PAK files, one per family, each with its own plot and a +50 % overlay
WhyThe worked PAKs on Canvas (JawModels, GyraModels, ConeModels, RollMillModels, PressureRollMillModels) are the reference for each family; open them after your own run and compare model lists and settings
Roll crushers and HPGR sit under "mills" in MODSIM's menu but use crusher-class models (slide 27). Write the code you find on the flowsheet

Common mistakes

Watch out

Setting typed in millimetres into a metre field. Every MODSIM parameter form has a "units of size" selector; leave it on metres and type 0.050, or switch it to mm and type 50, but never mix.

Watch out

CSS given to a primary model. JAW1, JAW2 and GYRA want the OPEN-side setting; CRSH reads its single setting as CSS for cones and OSS for jaws and gyratories (manual, section 7.1.1). Label the setting you used in the flowsheet annotation.

Also: unequal splitter fractions; comparing plots with different axis ranges; forgetting the +50 % overlay; a size mesh that stops above the CSS; product streams without annotation (the sheet demands the model name beside each machine); and drawing conclusions about capacity from a model that has no capacity term.
